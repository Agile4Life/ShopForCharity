# Responsive validation — 2026-10-10

The shared responsive stylesheet preserves the forest/paper theme and scroll animations while adapting public, customer and seller surfaces to their available width.

## Changes

- Fluid page gutters; grid children and long order/contact information can shrink and wrap.
- Cart, checkout, order details, settings and dashboard sections become one column on smaller screens. Product details retain two balanced columns on tablets and one on phones.
- Order item tables become labelled item cards on phones, including unit price, quantity and line total.
- Seller filter controls use an adaptive grid instead of collapsing into narrow, tall selects. Phone product cards and metrics use a single column below 380px.
- Account menus stay within the screen; action buttons wrap; forms, footer links and combo item controls adapt to narrow widths.
- Short landscape screens receive a shorter header and viewport-constrained modal with scrolling content.

`frontend/e2e/responsive.spec.ts` checks 25 page states per size: the storefront, product/combo details, cart, checkout, order success, guest lookup/details, three authentication pages, customer profile/orders/details, and eleven seller management/form pages. It verifies document width and visible control bounds, opens account menus, and types/saves a pickup point in its modal. Accepted customer orders include bank transfer information and stress long buyer names/emails.

Intentionally scrollable data tables, categories and seller navigation can scroll inside their own containers; the document itself must fit. Closed details panels and hidden elements are excluded from visible-control checks. Screenshots are saved for representative widths and failures.

## Reproduction commands

From `frontend`, with installed Playwright browsers and `PLAYWRIGHT_BROWSERS_PATH` pointing to `.browsers`:

```powershell
node node_modules/@playwright/test/cli.js test --workers=2
node node_modules/@playwright/test/cli.js test --config=playwright.responsive.config.ts --workers=2
```

The primary configuration covers desktop Chromium and Pixel 7 touch emulation. The additional configuration covers Firefox and WebKit, including catalog/cart/checkout flows, account/select controls, pickup calendar and the responsive matrix. Its independent port is reflected in the fixture origin; other external requests remain blocked. Run the commands sequentially, or set `E2E_REUSE_BUILD=1` for the additional configuration after the primary build has finished; rebuilding a shared `dist` during navigation invalidates in-flight asset requests.

The account menu links have explicit `tabIndex={0}` so WebKit includes them in keyboard navigation. The select control test checks the custom Chromium picker when supported and native keyboard selection otherwise.

These are local browser-engine and viewport tests with isolated API fixtures. They do not assert a deployment, physical-device testing, or a new production database audit.
